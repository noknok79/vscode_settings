# Infrastructure (Terraform) Instructions

## Scope

This repo owns **APIM configuration-as-code only** (APIs, policies, named values) against an
Azure API Management instance that is **provisioned and owned by a separate Infra team**.
Terraform here must **never** create or modify the `azurerm_api_management` resource itself —
always reference it via the `data "azurerm_api_management"` data source.

## Deployment Root

`Devops/apim-terraform` is the root deployed by `Devops/azure-pipelines-bff-container.yml` and is
authoritative for deployment. Apply every APIM policy/Terraform change there. `infrastructure/apim-terraform`
is a development/test root (sandbox/QAT tfvars, full OpenAPI spec); keep shared files
(`main.tf`, `variables.tf`, `outputs.tf`, `policies/`) identical between the two roots.

## Rules

- **All resources/config target Australia East** — the referenced APIM instance is provisioned in `australiaeast` by the Infra team (P-03 Data Sovereignty).
- **Managed Identity / Entra-only auth** — no access keys, no connection strings, no SAS tokens.
- **No secrets in `.tfvars` committed to source control** — use `*.tfvars` only for non-secret values (names, URLs, tenant/client IDs are not secrets); pass secrets via `TF_VAR_*` environment variables or a secure pipeline variable group.
- Every new API/policy addition gets its own resource block in `main.tf`; large XML policy bodies go in `policies/*.xml` or `policies/*.xml.tpl` and are loaded via `file()`/`templatefile()`.
- `main.tf` orchestrates resources — keep provider/version constraints in `providers.tf` / `versions.tf`, variables in `variables.tf`, outputs in `outputs.tf`.

## Resource Pattern

```hcl
# main.tf
data "azurerm_api_management" "apim" {
  name                = var.apim_name
  resource_group_name = var.resource_group_name
}

resource "azurerm_api_management_api" "my_api" {
  name                  = "my-api"
  resource_group_name   = data.azurerm_api_management.apim.resource_group_name
  api_management_name   = data.azurerm_api_management.apim.name
  display_name          = "My API"
  path                  = "my-api"
  protocols             = ["https"]
  service_url           = var.backend_url
  revision              = "1"
  subscription_required = false
}
```

## Policy Pattern (templated XML)

```hcl
resource "azurerm_api_management_policy" "global" {
  api_management_id = data.azurerm_api_management.apim.id
  xml_content = templatefile("${path.module}/policies/global.xml.tpl", {
    entra_login_host = var.entra_login_host
    allowed_origins   = local.effective_origins
  })
}
```

## Named Values (no secrets in plain XML)

```hcl
resource "azurerm_api_management_named_value" "entra_tenant_id" {
  name                = "entra-tenant-id"
  resource_group_name = data.azurerm_api_management.apim.resource_group_name
  api_management_name = data.azurerm_api_management.apim.name
  display_name        = "entra-tenant-id"
  value               = var.entra_id_tenant_id
  secret              = false
}
```

## Naming Conventions

| Resource | Pattern |
|----------|---------|
| API | `{feature}-api` |
| Named value | `{purpose}-{name}` (kebab-case) |
| Policy file | `policies/{scope}.xml` or `policies/{scope}.xml.tpl` |

## API Endpoint Exposure — OpenAPI Import (Enterprise Default)

- The generated BFF OpenAPI document is the canonical contract for the legacy BFF API and the
  domain APIs. Terraform filters and rebases that one document; never maintain independent
  hand-edited domain contracts.
- Plans, Users, Orders, and Pharmacies are exposed as separate APIs with suffixes under
  `bff/api/v1/{domain}`. Their imported operation paths and backend URLs are rebased together so
  existing gateway and BFF route URLs do not change.
- The legacy BFF API remains during the additive migration and continues to own Health Checks and
  the Sandbox wildcard fallback. A dedicated Health Checks API requires a separately approved
  cutover because both APIs cannot own the `bff` suffix at the same time.
- APIM uses an **OpenAPI import** (one explicit operation per endpoint, required for domain APIs and
  QAT/Production) or a **GET/POST/PUT/PATCH/DELETE wildcard fallback** on the legacy API (`/*`,
  Sandbox only).
- Controlled by `var.openapi_spec_path` in `main.tf`: empty (Sandbox default) keeps the
  legacy wildcard operations and does not create domain APIs; set to a generated OpenAPI
  document's path (e.g. `openapi/bff-api.json`) to import the legacy API and create the filtered
  domain APIs.
- The OpenAPI document is generated by CI from a **Sandbox-config build** (Swagger is
  compiled in for Debug/Sandbox only, never Release — see `ENABLE_SWAGGER` in
  `DBG.inDispensable.API.csproj`) via the Swashbuckle CLI, then published as the
  `bff-openapi-spec` pipeline artifact (`azure-pipelines-ci.yml`).
- QAT/Production `terraform apply` must download that artifact, place it at
  `infrastructure/apim-terraform/openapi/bff-api.json`, and pass
  `-var openapi_spec_path=openapi/bff-api.json`.
- Never hand-edit APIM operations imported from OpenAPI — change the BFF controller/Swagger
  annotations and regenerate the document instead, so APIM and the BFF contract can't drift.
- Before retiring the legacy API, verify every domain API with
  `scripts/verify-apim-operation-inventory.ps1` using `-OpenApiPathPrefix` and
  `-StripOpenApiPathPrefix`, then perform the Health Checks cutover as a separate deployment.

## Validation Before Deploying

```bash
terraform -chdir=infrastructure/apim-terraform fmt -check
terraform -chdir=infrastructure/apim-terraform validate

# Sandbox (wildcard mode)
terraform -chdir=infrastructure/apim-terraform plan -var-file=sandbox.tfvars

# Dev (when deploying to Dev environment)
terraform -chdir=infrastructure/apim-terraform plan -var-file=dev.tfvars

# QAT/Production (OpenAPI import) — after downloading the bff-openapi-spec artifact to
# infrastructure/apim-terraform/openapi/bff-api.json:
terraform -chdir=infrastructure/apim-terraform plan -var-file=test.tfvars -var openapi_spec_path=openapi/bff-api.json
```
