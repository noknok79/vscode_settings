# Technical Writing Standards

## Language

- Use professional technical English.
- Prefer concise, direct sentences.
- Avoid unnecessary repetition.
- Define unfamiliar acronyms.
- Maintain consistent terminology.

## Formatting

- Use GitHub Flavored Markdown.
- Use descriptive headings.
- Maintain logical heading hierarchy.
- Specify languages in code fences.
- Use tables for structured comparisons.
- Use numbered lists for procedures.
- Include Mermaid diagrams when useful.

## Technical Accuracy

- Verify statements against available source files.
- Do not fabricate configurations.
- Do not assume deployment success.
- Do not invent resource names or identifiers.
- Distinguish confirmed details from assumptions.
- Flag missing information explicitly.

## DevOps Documentation

When relevant, document:

- Infrastructure components
- CI/CD workflows
- Environment configuration
- Deployment prerequisites
- Security considerations
- Monitoring and logging
- Validation procedures
- Rollback and recovery

## Security

- Never include actual credentials.
- Redact tokens and secrets.
- Avoid exposing sensitive configuration.
- Use placeholders for confidential values.

## Quality

Documentation must be:

- Accurate
- Clear
- Reproducible
- Maintainable
- Version-control friendly
